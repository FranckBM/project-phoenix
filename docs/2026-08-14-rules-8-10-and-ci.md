## Bug found: GUID collision across 6 rule files

`sigma check` flagged `IdentifierCollisionIssue (HIGH)` — six rule files
were sharing the same placeholder GUID
(`31c929ea-e3a7-488f-8b43-f3179abcdf52`), left over from an early draft
template instead of each getting a fresh `[guid]::NewGuid()`. Affected:
`data_archive_exfil.yml`, `defender_tamper.yml`, `msf_powershell_payload.yml`,
`office_powershell_spawn.yml`, `ps_web_download.yml`,
`scheduled_task_persistence.yml`. Fixed by generating 6 unique GUIDs and
replacing each `id:` line individually. Also cleaned up a stray double-space
after `id:` in two of the files while in there.

## Bug found: `sigma check`'s ATT&CK tag validator ships with bad data

Four rules flagged `InvalidATTACKTagIssue (MEDIUM)` on
`attack.defense-evasion` (and, on `defender_tamper.yml` specifically, also
on `attack.t1562.001`). Traced this all the way down rather than just
renaming tags to make the warning disappear:

- Inspected the validator's actual bundled tactic list:

powershell

```powershell
  python -c "from sigma.data.mitre_attack import mitre_attack_tactics; print(mitre_attack_tactics)"
```

  Result showed no `defense-evasion` entry at all — instead `'TA0005':
'stealth'` and `'TA0112': 'defense-impairment'`, neither of which is the
real, official MITRE tactic name ("Defense Evasion").
- Confirmed the technique-ID side is also incomplete:

powershell

```powershell
  python -c "from sigma.data.mitre_attack import mitre_attack_techniques; print('T1562' in mitre_attack_techniques)"
```

  Returned `False` — T1562 isn't in the bundled dataset at all.
- `sigma check --help` had already hinted at this: the command's own
description reads *"Check Sigma rules for validity and best practices
**(not yet implemented)**."* Not a stale docstring — accurate.

**Decision:** did not rename tags to match the validator's incorrect data.
`attack.defense-evasion` is the correct, standard MITRE terminology and
stays as-is. Instead, excluded the specific broken validator from CI:

powershell

```powershell
  sigma check . -x attacktag
```

(Correct exclude name found via `sigma list validators` — two earlier
guesses, `attack_tag` and `attack-tag`, were both rejected by the CLI
before landing on the right one, `attacktag`, no underscore or hyphen.)

Result: 0 errors, 0 issues, clean run across all 10 rules.

## CI workflow shipped

Added `.github/workflows/sigma-lint.yml` — runs on every push/PR touching
`detection-rules/sigma/**.yml`:
1. `sigma check` (with `attacktag` excluded, per above)
2. `sigma convert -t lucene --without-pipeline` on every rule file, to
catch anything `check` might miss
